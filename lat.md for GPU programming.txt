Coding agent는 architect level (root folder에서 동작) 그리고 executor level (subsystem folder에서 locality를 가지고 동작)로 나뉘어 협업하는 구조야.

그러면 architect agent는 어떻게 design pattern 및 SKILL.md 체계를 갖추고 executor agent에 무엇을 전달해야 agent-ready metaprogramming이 될 수 있을까?
seam point, trace log item, invariants 등을 outcomes.md로 정리하면 될까?
attention (prefill, decode) 기준으로 체계적으로 분석 가이드해줘.

<workflow>
Pre-flight: read architecture.md, expected-outcomes.md, and design-patterns.md and write down plan.md
Execute: execute the plan.md 
Parity Test and Trace: Run parity tests against reference implementations, and measure its TTFT and throughtput
Fix and Report: If something fails, use the debugging guide, fix, and rerun. Finally generate reported-outcomes.md
Retrospect: update design-patterns.md if required, and write any engineering knowhow into retrospect.md

스키마:
CREATE TABLE IF NOT EXISTS sections (
  id TEXT PRIMARY KEY,           -- 섹션 식별자 (예: "architecture#Pipeline")
  file TEXT NOT NULL,             -- 파일명 (예: "architecture.md")
  heading TEXT NOT NULL,          -- 섹션 제목
  content TEXT NOT NULL,          -- 섹션 내용
  content_hash TEXT NOT NULL,     -- 내용 해시 (변경 감지용)
  embedding F32_BLOB(${dimensions}), -- 임베딩 벡터 (예: OpenAI text-embedding-3-small → 1536차원)
  updated_at INTEGER NOT NULL
);

CREATE INDEX IF NOT EXISTS sections_vec_idx ON sections (libsql_vector_idx(embedding));
