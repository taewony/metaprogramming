Step 01

시스템 모델

System Model

💡 개념 정의

개발하고자 하는 시스템의 구조, 요구사항, 흐름을 추상적으로 개념화하여 정신적 또는 문서화된 설계 모델(Mental & Structural Model)을 확립하는 최초 설계 단계입니다.

"웹으로 구현한 간단한 타이머를 만들어 줘, 바로 코드를 작성하지 말고, 먼저 전체 구현 순서와 파일별 핵심 로직을 정리한 Implementation_Plan.md 파일을 생성해 줘."

🛠️ hello-antigravity 실습 매핑

에이전트에게 즉흥적으로 코드를 짜게 하지 않고, 구조화된 아키텍처 가이드라인인 Implementation_Plan.md 설계를 지시하고 이에 합의하는 기획 단계에 대응합니다.

Implementation_Plan.md (구조 예시) markdown 
# Implementation Plan: Focus Timer
1. **Architecture Overview**
   - Single-page application using modern HTML5 semantic elements
   - Styled with custom CSS variables (themes, sizes, flexbox layout)
   - Powered by OOP based Javascript Timer core
2. **Components Specifications**
   - Display: Hour/Min/Sec digits with localized labels
   - Controls: Start, Pause, Reset action controls
   - Presets: Custom quick preset buttons (e.g., Pasta 8 mins)
Step 02

코드 구현

Implementation

💡 개념 정의

확립된 시스템 모델을 바탕으로, 실제 작동 가능한 소스 코드 파일들을 작성하고 개발 환경을 구축하여 설계를 구체물로 실현하는 단계입니다.

"현재 폴더에 hello.py 파일을 만들고 'Hello Antigravity!'를 출력하는 코드를 작성해 줘."

🛠️ hello-antigravity 실습 매핑

초기 프로젝트를 생성하고, `hello.py` 출력 스크립트 작성 및 `index.html`, `style.css`, `script.js`로 이루어진 타이머 애플리케이션의 골격을 실제 코딩하는 과정입니다.

hello.py python 
# Hello Antigravity Python Script
print('Hello Antigravity!')
script.js (Timer Class Constructor) javascript 
class Timer {
    constructor() {
        this.hoursElement = document.getElementById('hours');
        this.minutesElement = document.getElementById('minutes');
        this.secondsElement = document.getElementById('seconds');
        this.totalSeconds = 0;
        this.isRunning = false;
        this.initListeners();
    }
}
Step 03

평가 및 검증

Evaluation

💡 개념 정의

작성된 코드를 실행 환경(런타임, 브라우저 등)에서 가동시키며 테스트 케이스, 요구조건, 정적 코드 분석기를 통해 예상대로 완벽히 동작하는지 검사하는 단계입니다.

"파스타 타이머 기능을 추가해 줘, 파스타 버튼을 누르면 자동으로 8분 타이머가 시작되게 만들어 줘."

🛠️ hello-antigravity 실습 매핑

타이머를 직접 가동(Evaluation)하여 파스타 버튼(8분 자동 설정) 클릭 시의 시간 카운트다운 테스트, 영문 레이블의 한글화 변경 테스트, 다크 모드 ON/OFF 토글 동작성을 검증하는 과정입니다.

Step 04

객관적 증거

Evidence

💡 개념 정의

검증(Evaluation) 수행 중 포착되는 명확한 런타임 결과물입니다. 성공적인 작동 메트릭, 컴파일러 경고, 터미널 에러 스택 트레이스, 브라우저 렌더링 디버깅 로그 등이 여기에 해당합니다.

"@Terminal 내용을 보고 방금 실행한 코드에 오류가 났는지 확인해줘."

🛠️ hello-antigravity 실습 매핑

실제 브라우저의 콘솔 출력, 터미널(Terminal)의 컴파일 에러 메시지, 그리고 룰 및 린터 검사를 통과하지 못한 오류 등의 구체적 증거 데이터 수집 과정입니다.

Step 05

통찰

Insight

💡 개념 정의

증거(Evidence)로 획득된 데이터들을 정밀 분석하여, 에러가 발생한 메커니즘을 밝혀내고 구조적 결함이나 성능 병목, 혹은 협의된 룰과의 괴리를 근본적으로 해석해내는 단계입니다.

"@script.js#L39-54 이 코드가 어떻게 동작하는지 초보자도 알기 쉽게 설명해 줘."

🛠️ hello-antigravity 실습 매핑

수집된 에러(clearInterval 누락)의 원인을 발견하고, `@.antigravityrules`에 명시된 규칙(예: 한국어 독스트링 작성, 변수 명명 규칙)을 지키지 않아 생기는 스타일 일관성 문제를 이해하는 논리적 분석 단계입니다.

Antigravity Rules Check (Insight)
규칙 미준수: script.js 내 API Docstring 누락
통찰: 협업 및 메타프로그래밍의 유연성을 위해 한글 Docstring 추가가 시급함.
Step 06

의사결정

Decision

💡 개념 정의

통찰(Insight)을 기초로 삼아 결함을 치료하고 시스템 품질을 극대화하기 위해 구체적으로 어떤 모듈을 수정하고, 어떤 라이브러리 가이드(예: Material Design 3)를 반영할지 결정을 내리는 설계 수정 단계입니다.

"너는 테크니컬 라이터이자 UI 디자이너야... @directory reference 폴더에 있는 md 파일을 이용해서 지금 타이머의 디자인을 머터리얼 스타일로 변경해 줘."

🛠️ hello-antigravity 실습 매핑

공식 문서와 가이드라인(`docs/reference/material_design_3.md`)을 읽어들여 머터리얼 스타일을 반영하기로 의사 결정하고, `.antigravityrules` 룰북 규칙을 코드 전반에 전격 적용하기로 확정하는 과정입니다.

.antigravityrules (적용 컨벤션) yaml 
# 3. 코딩 컨벤션 (Coding Standards) 적용 결정
- **주석:** 모든 주요 함수와 클래스에는 '한국어'로 독스트링을 작성하세요.
- **명명 규칙:** Python 변수/함수는 snake_case, React 컴포넌트는 PascalCase 적용.
