05. 롤페이퍼 - 시스템 모델

System Model: Fullstack DB Schema Design
🧠 인지 모드: 관계형 DB 및 인프라 설계
💾 작동 기억 부하 (Working Memory): 55%

💡 인지 작용

사용자들이 생성하는 방(Boards)과 방문자들이 붙이는 포스트잇(Messages) 간의 1:N 관계형 데이터 스키마와 Supabase 연동 방안을 개념화하는 단계입니다.

"새로 만들 “디지털 롤링페이퍼” 서비스의 데이터베이스 테이블 구조와 컬럼을 설계해 줘. 수파베이스를 이용해서 서버 없이 백엔드를 구축하려고 해. 방(boards)을 만들면 방문자들이 그 보드에 여러 개의 메시지(messages/포스트잇)를 남기는 구조야. 관계를 명확히 포함해서 한눈에 보기 쉬운 표 형태로 정리해 줘."

🛠️ 실제 구현 대응

에이전트를 통해 `boards`와 `messages` 테이블의 외래키(Foreign Key) 매핑 명세서를 정의하고, 기획 요건을 관계형 테이블 표 형태로 가시화하는 논리 기획 과정입니다.

Database Table Schema design table 
* Table: boards
  - id (UUID, Primary Key)
  - title (text, 방 제목)
  - owner_id (UUID, 생성 사용자 식별자)
* Table: messages
  - id (bigint, Primary Key)
  - board_id (UUID, Foreign Key -> boards.id)
  - content (text, 포스트잇 내용)
  - x_pos (integer), y_pos (integer) -> 포스트잇 2D 좌표

supabase_init.sql sql 
CREATE TABLE boards (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  title TEXT NOT NULL,
  owner_id UUID REFERENCES auth.users(id)
);

CREATE TABLE messages (
  id BIGSERIAL PRIMARY KEY,
  board_id UUID REFERENCES boards(id) ON DELETE CASCADE,
  content TEXT NOT NULL,
  x_pos INT DEFAULT 0,
  y_pos INT DEFAULT 0
);
