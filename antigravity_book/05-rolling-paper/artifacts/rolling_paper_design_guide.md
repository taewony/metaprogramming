# 디지털 롤링페이퍼 서비스 UI/UX 디자인 콘셉트 및 설계 지침
(Digital Rolling Paper UI/UX Design Concept & Guidelines)

본 문서는 `05-rolling-paper` 프로젝트에서 다루는 실시간 풀스택 롤링페이퍼 서비스의 UI/UX 설계 지침과 동작 원리를 규정합니다. 이전 MBTI 프로젝트의 정적 UI 스타일링을 넘어, **상태(State) 보안, 실시간(Realtime) 동기화, 물리 인터랙션(Drag & Drop), 모바일 하이브리드(Expo WebView)**가 통합된 동적 UX 사양을 정의합니다.

---

## 1. 개요 및 설계 철학
롤링페이퍼 서비스는 다수의 사용자가 2차원 가상 보드 캔버스 공간에서 포스트잇(메시지)을 배치하고 공유하는 실시간 상호작용 서비스입니다. 
- **동적 반응성**: 모든 화면 갱신은 사용자 액션 및 실시간 DB 이벤트와 즉시 결합되어 새로고침 없이 유기적으로 처리되어야 합니다.
- **점진적 권한 노출**: 비로그인 방문자부터 방장(Owner)까지 인증 상태에 따른 최적화된 최소 권한 UI 분기를 적용하여 데이터의 무결성과 보안을 확보합니다.
- **크로스 플랫폼 일관성**: 웹뿐만 아니라 모바일 Expo 하이브리드 WebView 앱으로의 매끄러운 포팅을 고려한 레이아웃 가이드라인을 준수합니다.

---

## 2. 세션 상태 기반 다이내믹 UI 제어 지침 (Auth-driven UI)
사용자의 로그인 세션(`Supabase Auth Session`) 상태에 따라 UI 노출 요소와 액션 권한을 전격 분기합니다.

### 2.1 비로그인 방문자 (Public / Guest)
- **보드 조회 (Read-Only)**: 보드 페이지(`/board/:slug`)의 조회는 허용하되, 포스트잇 생성/수정/삭제 권한은 원천적으로 차단합니다.
- **UI 노출 제어**:
  - 우측 상단의 `[메시지 남기기]` 버튼을 숨기거나 비활성화하고, 로그인 페이지로 유도하는 `[로그인하고 메시지 남기기]` 링크/버튼을 배치합니다.
  - 마우스 오버 시 포스트잇 드래그 핸들 및 수정 힌트를 일절 제공하지 않습니다.
- **상호작용 차단**: 포스트잇 드래그(`mousedown` / `touchstart`) 동작이 가동되지 않도록 방어 로직을 적용합니다.

### 2.2 로그인 사용자 (Authenticated User)
- **UI 활성화**: `[메시지 남기기]` 버튼을 정상 노출하여 메시지 작성 모달(`PostItModal`)을 트리거합니다.
- **본인 메시지 제어**: 
  - 마우스 마운트 시 자신이 작성한 포스트잇(`owner_id`와 `auth.uid()` 일치)에만 드래그 앤 드롭 그랩 커서(`cursor: grab`) 및 마우스 오버 그림자 강화 효과를 부여합니다.
  - 본인의 포스트잇을 **더블 클릭 (Double Click)**할 경우, 수정용 모달(기존 content, senderName, color가 프리로드된 `editMode`)을 팝업합니다.

## 3. 포스트잇 물리 인터랙션 및 좌표 영속화 지침 (DND Canvas)
보드 내 포스트잇은 절대 좌표 공간을 기반으로 자유롭게 배치되는 동적 인터랙티브 캔버스를 따릅니다.

```
+-----------------------------------------------------------+
|  Board Canvas                                             |
|                                                           |
|    +----------------+                                     |
|    |  [Post-It]     |  (Long Click -> Drag -> Move)       |
|    |  "Hello!"      |  =======> [New position]            |
|    |  (x_pos,y_pos) |           (x_pos', y_pos')          |
|    +----------------+                 |                   |
+---------------------------------------|-------------------+
                                        v
                       [DB SQL Update] SET x_pos, y_pos
```

### 3.1 드래그 앤 드롭 (Drag & Drop) 물리 효과
- **드래그 핸들러**: 마우스 롱클릭 혹은 터치 스크린 롱프레스로 포스트잇을 잡는 행위를 인지합니다.
- **그랩 애니메이션**: 잡았을 때 잡는 손모양(`cursor: grabbing`) 상태로 변환하고 `scale(1.05)` 및 미세한 회전 효과를 통해 손끝 반응성을 극대화합니다.
- **좌표 보정**: 브라우저 뷰포트 크기와 무관하게 일정한 상대 좌표값을 유지하도록 컨테이너(보드 캔버스) 내 한계값 클램핑(Clamping) 처리를 필수 반영합니다.

### 3.2 실시간 좌표 영속화 (DB Persisting)
- 드래그 조작이 종료되어 포스트잇을 드롭하는 순간(`mouseup` / `touchend`), 해당 객체의 고유 ID와 최종 좌표값(`x_pos`, `y_pos`)을 Supabase Database API를 통해 갱신합니다.
- 예기치 못한 브라우저 종료 시에도 최종 배치 좌표가 영구 보존되어야 합니다.

## 4. 실시간 다중 사용자 동기화 지침 (Realtime Synchronization)
롤링페이퍼 서비스는 다중 접속 환경이므로 양방향 통신 채널에 기반하여 동기화 지연을 최소화합니다.

- **WebSocket 구독 (Subscribe Realtime)**:
  - 클라이언트가 특정 보드 채널에 접속하면 Supabase Database `messages` 테이블의 WAL 이벤트를 실시간 리슨합니다.
- **동적 리렌더링**:
  - 다른 참여자가 포스트잇을 생성(`INSERT`), 이동(`UPDATE` coordinates), 수정(`UPDATE` content), 삭제(`DELETE`)하는 즉시, 웹소켓 이벤트를 통해 나의 로컬 React State 배열을 동기화하고 새로고침 없이 즉각 가시 영역을 재렌더링합니다.
- **동시성 충돌 방지**: 동일한 포스트잇을 동시에 조작하지 않도록 조작 중인 객체는 시각적으로 타인에게 선점되었음을 밝히는 락(Lock) 피드백 설계 등을 권장합니다.

---

## 5. 모바일 하이브리드(WebView) 대응 및 최적화 지침
웹 서비스를 Expo React Native 웹뷰로 래핑하여 모바일 기기(Android, iOS)로 확장할 수 있도록 아래 네이티브 최적화 사양을 강제 적용합니다.

### 5.1 네이티브 스피너 (Central Spinner)
- 웹뷰 프레임워크가 초기 웹 페이지 리소스와 Supabase 세션을 커넥션하는 과정에서 발생할 수 있는 빈 화면 노출 상태를 방어하기 위해 화면 정중앙에 로딩 스피너(`ActivityIndicator`)를 띄워 사용자 피로도를 방지합니다.

### 5.2 Safe Area (안전 지대 설계)
- 아이폰의 노치(Notch) 영역, 안드로이드 상단 펀치홀 및 하단 네비게이션 가상 버튼바와 타이머/메시지 UI 가 가려지지 않도록 최상단 요소들에 모바일 기준의 여백 계산(Safe Area Padding)을 구현합니다.

### 5.3 안드로이드 물리 뒤로가기 버튼 연동
- 사용자가 안드로이드 하드웨어 백 버튼을 입력했을 때, 모바일 하이브리드 앱이 통째로 꺼지지 않고 웹뷰 내부 브라우저 히스토리에 따라 순차적으로 이전 보드나 홈 화면으로 `history.back()` 동작하도록 자바스크립트 브릿지 이벤트 수신기를 활성화해 주어야 합니다.
